## Conclusion

`SAL-P5-009` adds a pure offline Intel Agent evidence adapter:

```text
src/serenity_alpha_lab/application/intel_agent.py
tests/application/test_intel_agent_evidence_adapter.py
```

The adapter converts a prebuilt Intel `EvidenceBundle` plus concrete `PromptRunBinding` into a deterministic prompt payload, validates already-produced structured event output, and maps it to DSA-compatible news/intel fields. It consumes source-trust metadata generated by `SAL-P5-004`, preserving separate event, publication, observation and availability timestamps while excluding duplicate or malicious source records and marking stale or low-trust records as unsuitable for strong claims.

This task does not call a model, fetch news/search/social content, read evidence bodies, write Evidence Store, execute DSA Intel tools, start Worker loops, initialize Qlib runtime, validate final report citations, render reports, schedule production work or promote formal portfolio backtests.

## Evidence Rules

Intel Agent input is restricted to source-trust-backed market intelligence evidence:

| Evidence requirement | Rule |
|---|---|
| Kind | `EvidenceKind.UNSTRUCTURED_SOURCE` |
| Scope | `EvidenceEvaluationScope.MARKET_INTELLIGENCE` |
| Source schema | `research.source_trust@1.0.0` prompt-safe metadata |
| Prompt metadata | `metadata.source_trust` must include source id/type, URL/body hashes, trust, issue list and timestamps |
| LLM recompute | `metadata.llm_recompute_allowed=false` is required |
| Strong claims | Require at least one included source with `strong_claim_allowed=true` |
| Malicious content | Excluded from allowed evidence when source trust detects prompt/tool instructions |
| Duplicates | Excluded by repeated `cleaned_body_hash` / URL hash identity |
| Stale content | Included only as stale context, with `strong_claim_allowed=false` and corroboration required |

`EvidenceBundleBuilder` now prioritizes `unstructured_source` evidence for the `intel` role while preserving the existing decision-time, instrument, duplicate-content and token-budget guards.

## Time Semantics

The adapter keeps four timestamps separate:

- `event_time`: when the market event occurred or became relevant.
- `published_at`: when the source published the content.
- `observed_at`: when the platform or caller observed the source.
- `available_at`: when the evidence became available to the research run.

`available_at` must match the `EvidenceRecord.available_at`, and stale source classification is computed against the bundle decision time. Later Citation Validator and report rendering stages must preserve these fields instead of collapsing them into one ambiguous date.

## Output Rules

`finalize_output()` validates caller-provided structured output only:

- every citation references evidence included in the Intel prompt payload;
- citation dataset versions, run id, stage id and artifact hash match the cited `EvidenceRecord` lineage;
- every claim citation id exists in the structured citation list;
- Intel output cannot introduce `numeric_metric` claims;
- strong events require trustworthy source evidence from the current payload;
- event source evidence ids must be from the current allowed evidence set.

These checks make source trust and citation coverage machine-readable before later model routing, Citation Validator and report rendering tasks.

## DSA Compatibility

`IntelAgentResult.to_dsa_compatible_opinion()` returns a legacy Intel opinion surface:

```json
{
  "agent_name": "intel",
  "signal": "positive",
  "sentiment_score": 72,
  "reasoning": "...",
  "news_summary": "...",
  "raw_data": {"events": [], "claims": [], "citations": []}
}
```

`IntelAgentResult.to_dsa_dashboard_fields()` returns dashboard/report compatibility fields:

- `news_summary`
- `news_analysis`
- `intel_analysis`
- `sentiment_score`
- `sentiment_label`
- `key_events`
- `source_quality`
- `warnings` / `limitations`
- cited `citations`

The mapping is a compatibility layer only. It does not patch legacy DSA Agent runtime, register routes or fetch live intelligence sources.
